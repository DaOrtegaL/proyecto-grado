El problema

Hoy

  • Renovación e instalación manual, a veces por acceso remoto a cada terminal
  • Sin inventario centralizado ni responsables claros
  • Varios emisores (PKI interna y proveedores)
  • Poca trazabilidad de quién instaló qué

Riesgo

  • Vencimientos inesperados y fallas de autenticación mutua
  • Terminales POS indisponibles y servicios de pago afectados
  • Incidentes P1/P2 e intervenciones urgentes
  • Errores de instalación sin reversión

De una gestión manual y reactiva a una centralizada, preventiva, controlada y auditable

Objetivo y alcance

Diseñar, desarrollar y validar un módulo, integrable con My Store Health, que inventaríe, monitoree, alerte y gestione la renovación e instalación controlada de certificados X.509 en terminales POS con Windows 10 IoT.

Incluye

  • Inventario por PowerShell (solo lectura)
  • Alertas a 60 / 30 / 15 / 7 días
  • Aprobación con separación de funciones
  • Instalación controlada, verificación y reversión
  • Auditoría con integridad verificable
  • Indicadores y evidencia experimental

Excluye

  • No reemplaza las autoridades de certificación
  • No almacena ni transmite claves privadas
  • No trata datos de clientes ni de tarjetas
  • No ejecuta comandos arbitrarios ni operaciones destructivas
  • No instala en tiendas productivas sin autorización

Puesta en funcionamiento

Requisitos: Node.js ≥ 20 · npm ≥ 10 · no requiere Docker en modo simulación

cd proyecto-grado
Copy-Item .env.example .env       # MOCK_DATABASE=1 · defina JWT_ACCESS_SECRET y JWT_REFRESH_SECRET (≥ 32 caracteres)
npm install
npx prisma generate
npm run build:libs
npm run mock:reset                # datos de ejemplo en mock-database/ (fechas relativas a hoy)
npm run build -w @msh/api
npm run start -w @msh/api         # API  → http://localhost:3000   (Swagger: /api/docs)
npm run dev:web                   # Web  → http://localhost:5173

Variable clave: MOCK_DATABASE

1 = carpeta mock-database/ (47 archivos JSON, sin Docker)
0 = SQL Server con docker compose up --build (no verificado)

Comprobación

GET /api/v1/health debe responder "database":"MOCK_JSON", "executionMode":"SIMULATION" y "labModeEnabled":false.

Cómo se verifica

npm run test:unit          # dominio, base JSON, simulador y API (flujos completos)
npm run test:integration   # script PowerShell real, firma de scripts, claves privadas
npx playwright install chromium
npm run test:e2e           # E2E01–E2E05 en navegador

Alcance real y limitaciones

Importante aclarar

  • Todos los datos y resultados son sintéticos; no evidencian el efecto en tiendas reales
  • My Store Health: contrato propuesto con implementación simulada
  • Notificaciones solo internas (sin correo)
  • La verificación comprueba el reinventario, no un handshake mTLS real
  • No se declara TRL ni significancia estadística

Próximos pasos

  • Verificar con SQL Server
  • Autorización para un laboratorio real y mecanismo remoto aprobado
  • Línea base real (inventario, tickets, incidentes) y muestra efectiva
  • Cola con reintentos (BullMQ / Redis)
  • Piloto controlado y medición de indicadores
